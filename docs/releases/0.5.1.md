**Early preview, unsigned.** 0.5.1 adds a fifth engine (PySCF) and takes ORCA past a single point —
NMR and spin-spin couplings, TD-DFT, Raman and VCD, and transition-state, IRC and scan searches — and
adds a Multiwfn analysis sidecar, a cclib converter for foreign logs, ONIOM and ROA result parsing and
binary ChemDraw import. It also carries the ORCA and Psi4 scratch, packaging and CLI-clock fixes.
**There is no format change:** `schemaVersion` is still 3, and a project saved by 0.5.0 opens
unchanged.

## Upgrade

- **No breaking change.** `schemaVersion: 3` is unchanged, a 0.5.0 project opens here as it is, and
  run-record documents still export at `--schema-version 1`.
- **A 0.4.0 project is still refused by version.** That break arrived in 0.5.0 and is not re-opened;
  finish or export such a project in 0.4.0.
- **PySCF is optional.** It joins the engine list when you point the app at a Python that has `pyscf`
  (2.x, plus `geometric` for optimisations). Nothing else changes without it, and neither Python nor
  PySCF is bundled.

## New in 0.5.1

- **The PySCF engine.** HF and DFT single points, optimisations and frequencies (geomeTRIC, analytic
  Hessian), MP2, CCSD, CCSD(T), CASSCF single points, PCM/C-PCM solvation on a single point, and
  **TD-DFT** singlet roots with oscillator strengths and transition dipoles. The input is one fixed,
  reviewed Python deck and the result is a JSON record on stdout — no project field is ever
  interpolated into the script as code. Every method, basis, job type and solvent is validated by
  name before the deck is written.
- **ORCA beyond a single point.** NMR shieldings and spin-spin coupling tables, TD-DFT excited states
  with oscillator strengths, Raman and VCD spectra, and `OptTS`, IRC and relaxed scans — each parsed
  into the same result shapes the Gaussian reader produces.
- **A Multiwfn analysis sidecar** in an Analyse block: QTAIM basin integration, ESP surface
  statistics, ELF/LOL cubes and RDG–NCI points from a **user-installed** Multiwfn 3.8 binary, run in
  `-silent` batch mode. `run.json` records its version, the exact menu script, the input SHA-256 and
  the required citation; the binary is never bundled.
- **A cclib converter sidecar.** A log from NWChem, GAMESS, Q-Chem, Molpro, CFOUR or Dalton is
  converted to Chemical JSON by a user-installed `cclib`, so it imports as `kind: "imported"` with
  program, version, method, basis and source hash — without a second parser family in the app.
- **ONIOM result parsing:** extrapolated energies, gridpoint components, layer counts and link-atom
  cuts, with a layer SCF never shown as the ONIOM total.
- **ROA intensities and invariants** read from a Gaussian log.
- **Binary ChemDraw `.cdx` drawings** imported as one record per fragment.
- **Explicit solvent clusters** in a `prepare` block: a deterministic solvation shell rather than a
  continuum model.
- **Matrix element requests** (`rwf`) from a Gaussian block (Tier 1), and more of what an fchk
  carries — job status, character fields and MO dimensions.
- **Machine settings** stored outside the project, and a **floating run console** that remembers its
  position.
- **A validation matrix** over the reference cases, tabulated by `ncs validation`, with PySCF ladder
  rungs executed on the interpreter you point it at.
- **ADR 0002 defines the explorer**, the sixth program role: a program that navigates a potential
  energy surface exposed by a calculator and returns a saddle, path or profile. It amends ADR 0001
  §2.5 and adds a gradient/Hessian capability declaration to the engine contract.

## Fixed

- **Psi4's scratch files.** Psi4 wrote its integrals and DIIS files to `PSI_SCRATCH`, which defaults
  to `/tmp`; an 84-atom def2-TZVP job on a laptop filled that tmpfs and died with `WRITE failed … No
  space left on device`, a message that never names the cause. Every run now writes to its own
  `scratch/` folder, a launch whose scratch filesystem has under 1 GiB free is refused before it
  starts, and a run that still exhausts it records `scratch.exhausted` with the folder and the free
  space (#283).
- **`ncs run` no longer kills a healthy queue at one hour.** `--timeout` is the watcher's clock, not
  a task limit: each task keeps the project's `runner.timeoutSeconds` budget. A queue stopped by the
  watcher is left `paused` with its running task `interrupted`, so a later run resumes it, and the
  message names the block that was running and the value that would let it finish (#305).
- **The packaged app ships `src/data`**, so its JSON reference tables resolve (#299).
- The run console is scoped to the open project and a project swap clears queue history.
- Companion binaries are taken from `PATH`, and a signalled child is reported instead of passing.
- The engines page matches the code again: ORCA lists `TD-DFT`, `Opt=TS`, `IRC` and `Scan`, and the
  `.gbw` hand-off is no longer described as unimplemented.
- Psi4 and the schema resolve label/key method names, a null prepare energy can be saved, and a dry
  run no longer spawns a prepare converter.

## What this release does not claim

- **No app-driven run against a licensed Gaussian, xTB, ORCA, CREST or Psi4 binary.** The engine
  parsers are pinned by real logs — Gaussian 09 and 16, ORCA 6.1.1 (NMR, TD-DFT, Raman/VCD, OptTS,
  IRC and scan runs committed as fixtures), Psi4 1.11 — and the app's own run console driving a
  licensed job end to end on that machine remains unverified.
- **PySCF records are real runs of the deck, not of the app's runner.** Fifteen records from PySCF
  2.15.0 (HF, B3LYP, Opt, Freq, Opt Freq, PCM, three CASSCF cases, MP2, CCSD, CCSD(T), two TD-DFT
  cases and a deliberately failed SCF) are fixtures; HF and B3LYP/def2-SVP water agree with Psi4
  1.11 to 5.6 × 10⁻¹¹ and 1.7 × 10⁻⁷ Eh. The deck was executed directly under an interpreter, not
  through the app.
- **Multiwfn has not been run here.** Its fixtures are hand-written transcripts in the 3.8 layout that
  test the normaliser; no test claims agreement with a real Multiwfn run, and the guide says so.
- **The sidecars are not embedded in the installer.** Tautomer enumeration, the AIMNet2 scorer, the
  Multiwfn block and the cclib converter each need your own binary or Python environment and, for the
  scripts, the file from this repository at the release tag. None is bundled, and a missing one fails
  the block by name instead of producing a result.
- **ROA is read, but only a Gaussian 09 log is pinned.** No public Gaussian 16 B.01+ `Freq=ROA` log
  was available, so that revision stays unverified.
- **ONIOM input construction is not implemented**, only result parsing; the app does not write a
  route it cannot run and parse.
- **Windows sidecar runtime tests are skipped.** The Windows installer is built and the suite runs on
  windows-latest; the POSIX-only sidecar runtime tests are skipped there rather than faked.
- **Installers are unsigned**, have not been installed on a clean machine, and there is no macOS
  build.

## Verify your download

Both artifacts are unsigned. `SHA256SUMS`, a per-platform CycloneDX SBOM and a build-provenance
attestation accompany this release; the attestation can be checked with
`gh attestation verify <file> --repo xharl/nodechem-studio`.

There is no telemetry, no account and no paid tier. Neither artifact installs Gaussian, xTB, ORCA,
PSi4, PySCF, CREST, Open Babel, RDKit, torch or Multiwfn — the app drives them where they already are.
